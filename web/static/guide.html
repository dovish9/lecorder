Lecorder 사용 안내

Lecorder는 브라우저에서 녹음하거나 기존 미디어 파일을 업로드해 로컬 whisper.cpp로 전사하는 macOS용 작업 도구입니다. 원본 오디오와 타임스탬프가 포함된 Markdown을 지정한 폴더에 저장하며, 선택한 경우에만 로컬 Qwen3가 수정 후보와 문단 경계를 제안합니다.

대시보드
127.0.0.1:5055
음성 인식
whisper.cpp · large-v3
음성 감지
Silero VAD v6.2.0
선택 검수
Ollama · qwen3:8b-q4_K_M
결과물
원본 미디어 + Markdown
로컬 우선 대시보드, Whisper, Ollama는 기본적으로 127.0.0.1에서만 통신합니다. 녹음, 전사 결과, 강의 설정과 작업 이력은 사용자의 Mac 지정 폴더와 로컬 SQLite에 남습니다.

01Lecorder란

Lecorder의 역할은 녹음을 받는 순간부터 결과 파일이 완성될 때까지의 로컬 작업 흐름을 한 화면에서 관리하는 것입니다.

브라우저 대시보드

강의 설정, 녹음, 파일 업로드, 대기열, 결과물 탐색과 수정 제안 검토를 담당합니다.

Flask 백엔드

녹음 조각과 업로드를 보관하고 SQLite 상태, 단일 작업 대기열, 파일 저장을 관리합니다.

whisper.cpp

FFmpeg로 변환한 16kHz 모노 WAV를 large-v3와 Silero VAD로 전사합니다.

Ollama / Qwen3

선택 기능입니다. 전사문을 다시 쓰지 않고 단어 오인식 후보와 의미상 문단 경계를 구조화된 JSON으로 제안합니다.

데이터저장 위치와 용도
완성된 결과LECORDER_OUTPUT_DIR에 원본 확장자의 미디어와 같은 이름의 .md 저장
강의·작업 이력web/data/lecorder.db에 강의 설정, 처리 상태, 품질 지표와 수정 제안 저장
진행 중 원본web/data/recordings/에 업로드 원본 또는 서버가 받은 녹음 조각 임시 보관
브라우저 복구본IndexedDB에 서버 전송 전 녹음 조각과 녹음 세션 정보 보관

02처음 설치하기

Homebrew가 설치된 Apple Silicon Mac을 기준으로 합니다. Ollama는 선택 기능이지만, 아래에는 Qwen3 검수까지 사용하는 전체 설치 과정을 적었습니다.

  1. 기본 도구 설치

    Git은 소스 내려받기, CMake는 whisper.cpp 빌드, FFmpeg는 미디어 변환, Python은 Lecorder 실행에 사용합니다. brew install ollama는 Ollama 실행 파일도 함께 설치합니다.

    brew update
brew install git cmake ffmpeg python ollama

    설치 확인: git --version · cmake --version · ffmpeg -version · python3 --version · ollama --version

  2. Lecorder 전용 Python 환경 준비

    프로젝트 폴더에서 가상환경을 만들고 Flask와 Requests를 설치합니다. start.command는 .venv/bin/python을 우선 사용합니다.

    python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
mkdir -p output
chmod +x start.command
  3. whisper.cpp 내려받기와 빌드

    기본 설정은 Lecorder 프로젝트와 whisper.cpp가 같은 상위 폴더에 있다고 가정합니다. Apple Silicon의 기본 CMake 빌드는 Metal 가속을 사용합니다.

    git clone https://github.com/ggml-org/whisper.cpp.git ../whisper.cpp
(
  cd ../whisper.cpp
  cmake -B build
  cmake --build build -j --config Release
)

    이미 저장소가 있다면 다시 복제하지 말고 그 폴더에서 git pull 후 두 CMake 명령만 실행하세요.

  4. Whisper large-v3와 Silero VAD 모델 설치

    Lecorder는 다국어 large-v3 모델과 침묵 구간을 건너뛰는 Silero VAD v6.2.0 파일을 정확히 아래 이름으로 찾습니다.

    (
  cd ../whisper.cpp
  sh ./models/download-ggml-model.sh large-v3
  ./models/download-vad-model.sh silero-v6.2.0

  test -x ./build/bin/whisper-server && echo "whisper-server OK"
  test -f ./models/ggml-large-v3.bin && echo "large-v3 OK"
  test -f ./models/ggml-silero-v6.2.0.bin && echo "Silero VAD OK"
)
  5. Ollama 자동 실행과 Qwen3 설치

    Ollama를 Homebrew 서비스로 시작하면 지금 실행되는 동시에 macOS 로그인 후에도 자동으로 시작됩니다. 그다음 Lecorder의 기본 검수 모델을 내려받습니다.

    brew services start ollama
ollama pull qwen3:8b-q4_K_M
ollama pull qwen3.5:9b

# 설치 상태 확인
brew services list | grep ollama
ollama list

    brew services list에서 Ollama가 started이고, ollama list에 qwen3:8b-q4_K_M이 보이면 준비된 상태입니다.

    Qwen3 검수를 사용하지 않을 경우 Ollama 설치와 모델 다운로드는 생략할 수 있습니다. 해당 강의에서 Qwen3 문맥 검수도 끄세요.

  6. 최초 실행

    프로젝트 폴더에서 실행하거나 Finder에서 start.command를 더블클릭합니다. macOS가 차단하면 파일을 Control-클릭한 뒤 열기를 선택하세요.

    ./start.command

    start.command는 의존성과 포트를 확인하고 Flask 대시보드를 엽니다. Whisper 모델은 전사 시에만 로드하며, 마지막 음성 인식 후 60초간 새 작업이 없으면 메모리에서 해제합니다. 종료할 때는 실행 터미널에서 Ctrl+C를 누릅니다.

서비스기본 주소실행 주체
Lecorder127.0.0.1:5055start.command
whisper.cpp127.0.0.1:8080Lecorder가 전사 시 자동 실행
Ollama127.0.0.1:11434Homebrew 서비스

03경로 설정

대시보드 오른쪽 위 설정 버튼에서 아래 세 경로를 수정할 수 있습니다. 상대경로는 Lecorder 프로젝트 루트를 기준으로 해석됩니다. 저장할 때 폴더 존재 여부를 검증하고, 화면에는 whisper-server와 두 모델의 준비 상태를 따로 표시합니다.

환경 변수의미
LECORDER_DIRapp.py와 web/backend가 있는 프로젝트 폴더. 기본값 .
LECORDER_OUTPUT_DIR완성된 원본 미디어와 Markdown을 저장할 기존 폴더. 기본값 output
NOTE_VISION_MODEL강의노트 이미지 분석 모델. 기본값 qwen3.5:9b
OLLAMA_MODEL검수에 사용할 설치된 Ollama 모델. 기본값 qwen3:8b-q4_K_M

start.command로 실행 중이면 경로 저장 후 Whisper 프로세스를 정리하고 앱이 자동으로 다시 시작됩니다. 모델은 다음 전사 시 다시 로드합니다. python app.py로 직접 실행했다면 직접 재시작해야 합니다.

고급 설정

LECORDER_PORT대시보드 포트, 기본 5055
WHISPER_PORTwhisper-server 포트, 기본 8080
WHISPER_URL명시하면 외부 Whisper 서버를 사용합니다. 외부 서버의 로드·종료는 직접 관리합니다.
WHISPER_IDLE_SECONDS음성 인식 후 모델 해제까지 유예 시간, 기본 60초
OLLAMA_URLOllama chat API 주소, 기본 http://127.0.0.1:11434/api/chat
WHISPER_LOW_CONFIDENCE재확인 대상 평균 로그확률 기준, 기본 -0.65
WHISPER_RETRY_MAX_GROUPS한 작업에서 재확인할 최대 묶음 수, 기본 4
WHISPER_RETRY_MAX_SECONDS새 재확인 묶음을 시작하는 시간 한도, 기본 90초

출력 폴더를 바꾸면 이후 완료되는 작업부터 새 위치에 저장됩니다. 기존 결과물과 작업 이력은 자동으로 이동하지 않습니다.

05사용 흐름

01강의 선택강의 화면에서 프로필을 만들고 한국어·영어·자동 감지 중 언어를 선택합니다.
02강의노트 등록PDF·이미지·PPTX를 강의에 등록합니다. 추출 키워드의 포함·제외를 선택하고, 녹음을 시작한 뒤 하단 컨트롤 위에서 노트 하나 또는 사용 안 함을 선택합니다. 업로드·다시 전사하기에서도 노트를 선택할 수 있습니다. 개요에서는 전체 내용을, 학습 정리에서는 페이지 이미지와 Markdown 설명을 함께 봅니다. 키워드 출처는 해당 학습 정리로 이동하고, 원문 탭에서 OCR 결과를 확인합니다.
03처리 방식 선택가독성 자동 정리는 Qwen3가 찾은 의미 경계로 문단을 구성하고, Qwen3 문맥 검수는 단어 수정 후보를 만듭니다. 두 옵션은 강의별로 기억됩니다.
04녹음 또는 업로드녹음 화면에서 마이크를 녹음하거나 지원되는 오디오·동영상 파일을 업로드합니다. 작업을 시작할 때 현재 강의 설정이 해당 작업에 복사됩니다.
05대기열 확인전사는 한 번에 하나씩 처리됩니다. 앞 작업이 처리 중이어도 다음 녹음이나 업로드를 대기열에 추가할 수 있습니다.
06결과와 이력 확인저장소는 실제 출력 폴더를 읽어 음성과 Markdown을 묶어 보여 줍니다. 최근 작업은 상태, 시간, 품질 지표, 재시도와 중단 기능을 제공합니다.
07수정 제안 검토각 후보의 해당 시간 원음을 듣고 승인하거나 거절합니다. 승인한 항목만 현재 Markdown에 반영됩니다.

06전사 파이프라인

한 작업은 원본을 먼저 보존한 뒤 변환, 1차 전사, 제한적 재확인, 규칙 적용, 선택 검수, 원자적 저장 순서로 처리됩니다.

01작업 접수업로드 파일은 작업 폴더에 먼저 복사합니다. 브라우저 녹음은 5초 조각으로 생성되어 IndexedDB에 기록된 뒤 서버로 전송되고, 종료할 때 순서대로 하나의 원본으로 결합됩니다.
02단일 대기열SQLite에 작업과 당시의 강의 설정을 기록하고 단일 소비자 스레드가 등록 순서대로 처리합니다. 앱 재시작 시 queued 작업은 다시 대기열에 넣습니다.
03오디오 표준화FFmpeg가 입력 미디어를 Whisper용 16kHz · mono · PCM s16le WAV로 변환합니다. 입력 확장자는 결과 원본을 저장할 때 그대로 유지합니다.
04Whisper 1차 전사음성을 약 120초씩 가까운 침묵 지점에서 나눕니다. 침묵을 찾지 못하면 경계에 2초 문맥을 겹칩니다. 요청마다 이전 전사의 텍스트 상태를 초기화하고, large-v3와 Silero VAD로 각 구간을 전사합니다. 자동 인식 힌트는 실제 모델 토큰 96개 이내로 선별하며 발화 시각은 원본 기준으로 보존합니다.
051차 품질 보호60초 이상 파일에서 마지막 발화가 전체 길이의 절반 전에 끝나거나 인식된 발화 시간이 전체의 15%보다 짧으면 VAD 누락으로 판단합니다. 또한 신뢰도와 무관하게 긴 동일 문장이 연속 구간이나 전체 발화의 큰 비율을 차지하면 반복 붕괴로 판단합니다. 반복 붕괴 시 해당 구간만 과거 문맥·VAD·힌트 없이 beam search로 다시 읽으며, 재전사도 반복되면 잘못된 결과를 저장하지 않고 작업을 실패 처리합니다.
06저신뢰 구간 재확인평균 로그확률이 기본 -0.65보다 낮은 인접 발화를 묶고 앞뒤 여유를 포함한 최대 30초 클립으로 다시 읽습니다. 기본 최대 4묶음·90초 안에서 beam size 5로 시도하며, 신뢰도가 개선되거나 힌트 용어가 늘면서 품질이 유지되는 경우에만 원래 구간을 교체합니다. 빈 결과, 과도한 길이 변화와 반복 문장은 거절합니다.
07자동 힌트 사용선택한 강의노트의 키워드를 사용합니다. 수동 인식 힌트와 기계적인 문자열 교정은 사용하지 않습니다.
08Qwen3 선택 검수검수를 켠 경우 약 1,800자 단위로 나누어 단어 오인식 후보를 요청합니다. 가독성 자동 정리도 켰다면 같은 요청에서 문단 경계를 함께 판단해 중복 모델 호출을 줄입니다. 각 묶음에는 앞뒤 최대 3개 발화를 문맥으로 제공하며, 잘린 JSON은 더 작은 묶음으로 나눠 재시도합니다.
09Markdown 구성승인 전의 단어 후보는 본문에 적용하지 않습니다. Qwen3가 반환한 문단 경계만 선택 설정에 따라 반영하고, 각 문단 시작 시각에 원본 오디오 링크를 단 Markdown을 만듭니다.
10안전한 저장출력 폴더의 숨김 임시파일에 원본과 Markdown을 먼저 만든 뒤 최종 이름으로 교체합니다. 같은 이름이 있으면 (2), (3)을 붙여 기존 파일을 덮어쓰지 않습니다. 성공 후 작업용 임시 폴더를 삭제합니다.

강의 옵션에 따른 차이

07선택: LLM의 검수와 승인

Qwen3는 완성된 전사문을 다시 작성하지 않습니다. 단어 검수와 문단 판단을 하나의 구조화된 JSON 응답으로 받고, 각 결과는 기존 검증 규칙으로 따로 확인합니다.

  • 허용하는 수정 유형은 발음이 가까운 ASR 오인식과 발음이 가까운 전문용어 오인식뿐입니다.
  • 후보는 원문과 대체문이 각각 1~3어절, 24자 이하여야 하며 현재 발화에 원문이 실제로 있어야 합니다.
  • 신뢰도 0.80 미만, 숫자 변경, 문장부호 포함, 낮은 음성 유사도, 문법·문체·자연스러움을 이유로 든 후보는 폐기합니다.
  • 번역, 맞춤법·띄어쓰기 교정, 조사·어미 수정, 요약, 사실 교정, 의미가 다른 표현으로의 교체는 허용하지 않습니다.
  • 문단 경계는 주제 전환, 정의에서 예시로의 전환, 질문·답변 종료와 같이 의미 변화가 분명할 때만 사용합니다.

사용자가 승인하면 해당 발화의 첫 일치 구절만 바꾸어 현재 Markdown을 안전하게 다시 씁니다. 다른 작업에 적용되는 영구 교정 규칙은 만들지 않습니다. 거절한 후보는 상태만 기록하며 본문을 바꾸지 않습니다.

생성되는 Markdown

노트에는 강의명, 녹음 시각, 길이, 언어, Whisper·검수 모델, 원본 파일명이 YAML 메타데이터로 들어갑니다. 본문에는 전체 녹음 링크와 문단 시작 시각별 링크가 생성되므로 같은 폴더의 원본으로 바로 이동할 수 있습니다.

08실패 처리와 복구

  • 녹음 중 서버 연결 끊김: 전송 전에 IndexedDB에 저장된 조각을 유지하고 상태 갱신 때 다시 전송합니다.
  • 녹음 중 탭 또는 앱 종료: 앱 재시작 시 SQLite의 해당 작업을 recoverable로 바꾸고, 브라우저 세션과 조각이 남아 있으면 자동으로 복구해 대기열에 넣습니다.
  • 일부 조각 누락: 정상 종료 때는 누락을 오류로 처리합니다. 최근 작업의 남은 녹음 복구는 처음부터 연속으로 남아 있는 조각만 결합해 복구할 수 있습니다.
  • 처리 중 앱 종료: 진행 중이던 작업은 failed로 전환됩니다. 임시 원본이 남아 있으면 다시 처리로 처음부터 재시도합니다.
  • 사용자 중단: 대기 또는 처리 중인 작업을 중단하면 전사 결과와 제안은 지우고, 녹음 제목과 같은 이름의 원본 미디어만 보존합니다. 중단 상태는 보관함에서 별도로 표시됩니다.
  • Whisper 실패: 작업은 실패 상태와 오류 메시지를 남기고 원본 음성을 즉시 저장 경로에도 복사합니다. 재처리용 작업 원본 역시 유지하며, 한 작업의 실패가 대기열 스레드 전체를 멈추지는 않습니다.
  • 결과 파일 충돌: 기존 음성 또는 Markdown 어느 한쪽과 이름이 겹쳐도 번호를 붙여 두 파일의 이름을 함께 맞춥니다.

브라우저 녹음 중에는 마지막 조각을 확실히 만들 수 있도록 탭 닫기 경고가 표시됩니다. 가능하면 먼저 녹음 종료 버튼을 누르고 대기열 등록 메시지를 확인하세요.

09트러블슈팅

  1. 서비스 상태 확인

    대시보드 위 상태 표시에서 Whisper, Ollama와 선택한 Qwen3 모델의 준비 여부를 확인합니다. Qwen3는 선택 기능이므로 없어도 Whisper 전사와 저장은 가능합니다.

  2. 짧은 샘플 처리

    녹음 또는 파일 하나를 처리해 출력 폴더에 원본과 같은 이름의 Markdown이 함께 생기는지 확인합니다.

  3. Markdown 확인

    YAML 메타데이터, 녹음 듣기 링크, 문단별 타임스탬프 링크가 올바른 원본 파일을 가리키는지 확인합니다.

  4. Qwen3 검수 확인

    검수를 켠다면 수정 후보의 원음을 재생하고 승인·거절해 봅니다. 승인 후 현재 Markdown만 바뀌어야 합니다.

  5. 회귀 테스트 실행
    .venv/bin/python -m unittest discover -s tests -v
